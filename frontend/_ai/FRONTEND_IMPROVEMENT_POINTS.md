# Frontend 소스 코드 개선 제안

현재 `frontend` 디렉터리의 소스 코드를 분석한 결과, 초기 개발 단계로 보이며 더 나은 확장성과 유지보수성을 위해 다음과 같은 개선점을 제안합니다.

## 1. 컴포넌트 기반 아키텍처 도입

**문제점:**
- `components/posts`, `components/comments` 디렉터리가 비어있습니다. 게시글 목록, 게시글 아이템, 댓글 등 핵심 UI가 컴포넌트로 분리되지 않았습니다.
- `(auth)/login/page.tsx`의 로그인 폼이 페이지 내에 직접 작성되어 있어 재사용이 어렵습니다.

**개선 방안:**
- **게시판 컴포넌트화**: `components/posts` 디렉터리 내에 다음과 같은 컴포넌트를 생성합니다.
  - `PostList.tsx`: 게시글 목록 전체를 감싸는 컨테이너 컴포넌트.
  - `PostItem.tsx`: 개별 게시글을 표시하는 컴포넌트.
  - `PostForm.tsx`: 새 글 작성 및 수정을 위한 폼 컴포넌트.
- **인증 컴포넌트화**: `(auth)/login/page.tsx`의 폼 로직을 `components/auth/LoginForm.tsx`와 같이 별도 컴포넌트로 분리합니다.
- **공용 컴포넌트 생성**: `components/common` 또는 `components/ui` 디렉터리를 만들어 `Button.tsx`, `Input.tsx`, `Card.tsx` 등 프로젝트 전반에서 사용될 범용적인 UI 컴포넌트를 만듭니다.

## 2. 전역 상태 관리 전략 수립

**문제점:**
- `login/page.tsx`에서 `useState`를 사용해 지역 상태를 관리하고 있으나, 로그인 후 사용자 정보(토큰, 프로필)와 같은 전역 상태를 관리할 전략이 부재합니다.

**개선 방안:**
- **React Context API 활용**: 간단한 전역 상태(예: 로그인 여부, 사용자 정보, 테마) 관리를 위해 `src/context/AuthContext.tsx`를 생성하여 사용자 인증 상태를 관리합니다.
- **Zustand 또는 Jotai 도입**: Context API보다 더 복잡하고 성능 최적화가 필요한 상태 관리를 위해 가벼운 상태 관리 라이브러리 도입을 고려합니다.
- **React Query (TanStack Query) 도입**: 서버 상태(API 데이터) 관리를 위해 필수적으로 도입하는 것을 권장합니다. API 요청에 대한 로딩, 에러 처리, 캐싱, 데이터 동기화 등을 매우 효율적으로 관리할 수 있습니다.

## 3. 스타일링 및 디자인 시스템 개선

**문제점:**
- `login/page.tsx` 등에서 Tailwind CSS 유틸리티 클래스가 JSX 내에 길게 나열되어 가독성이 떨어지고 일관성 유지가 어렵습니다.

**개선 방안:**
- **`cva` (Class Variance Authority) 도입**: 컴포넌트의 여러 변형(variant)에 대한 스타일을 체계적으로 관리하기 위해 `cva`를 사용합니다. 예를 들어, 버튼의 `primary`, `secondary`, `danger` 스타일에 대한 클래스를 미리 정의해두고 `props`로 쉽게 제어할 수 있습니다.
- **`tailwind.config.ts` 확장**: 프로젝트의 디자인 시스템(색상, 폰트 크기, 간격 등)을 `tailwind.config.ts`의 `theme` 객체에 명확하게 정의하고, 코드에서는 정의된 값을 사용합니다. (예: `bg-blue-500` 대신 `bg-primary`)
- **`@apply` 지양**: 가급적 `@apply` 대신 `cva`나 컴포지션 기반으로 스타일을 조합하여 일관성을 유지합니다.

## 4. 코드 구조 및 역할 분리

**문제점:**
- API 요청 로직이 컴포넌트 내에 직접 작성될 가능성이 높습니다. (현재는 `TODO`로만 표시됨)
- 재사용 가능한 로직(커스텀 훅)을 위한 구조가 없습니다.
- `app/page.tsx`가 Next.js 기본 페이지로 남아있습니다.

**개선 방안:**
- **API 서비스 레이어 분리**: `src/lib/api` 또는 `src/services` 디렉터리를 만들어 백엔드 API와 통신하는 함수들을 모듈화합니다. (예: `getPosts`, `loginUser` 등)
- **커스텀 훅(Hook) 활용**: `src/hooks` 디렉터리를 생성하고, 반복되는 로직을 커스텀 훅으로 분리합니다. (예: `useAuth.ts`, `usePosts.ts`)
- **라우팅 및 페이지 정리**:
  - `app/page.tsx`를 실제 애플리케이션의 메인 페이지(예: 게시판 목록)로 리디렉션하거나, 의미 있는 대시보드 페이지로 구현합니다.
  - `(board)/first.tsx`는 `(board)/page.tsx`로 변경하여 게시판 목록의 기본 페이지 역할을 하도록 수정하는 것을 권장합니다.

## 5. 사용자 경험(UX) 개선

**문제점:**
- `Header.tsx`가 사용자의 로그인 상태와 관계없이 항상 '로그인', '회원가입' 링크를 보여줍니다.
- `login/page.tsx`의 폼 제출 시 로딩 상태나 API 요청 실패 시 에러 메시지를 처리하는 로직이 없습니다.

**개선 방안:**
- **동적 헤더 구현**: `AuthContext`나 상태 관리 라이브러리에서 사용자 정보를 가져와 로그인 상태에 따라 '내 정보', '로그아웃' 또는 '로그인', '회원가입' 링크를 조건부 렌더링합니다.
- **로딩 및 에러 상태 처리**:
  - 폼 제출 버튼을 눌렀을 때 버튼을 비활성화하고 로딩 스피너를 표시합니다.
  - API 요청이 실패하면 사용자에게 `alert`나 토스트 메시지를 통해 명확한 피드백을 제공합니다.
